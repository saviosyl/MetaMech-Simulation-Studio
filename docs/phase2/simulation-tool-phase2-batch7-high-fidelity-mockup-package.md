## B) Visual pairing decisions

- **Primary visual (section 1):** `sim-hero-main-light-v01.png`  
  Why: strongest premium + practical composition for product-first impression.

- **Benefits proof visual (section 3):** `sim-proof-connection-transfer-light-v01.png`  
  Why: quickly communicates technical credibility of handoff logic.

- **Process visual (section 4):** `sim-proof-flow-behavior-light-v01.png`  
  Why: best fit for showing dynamic line behavior in “How it works”.

- **Reliability visual (section 5):** `sim-proof-transfer-reliability-light-v01.png`  
  Why: reinforces stability/depth without distracting from persona/use-case text.

- **Pricing support visual (section 6):** `sim-pricing-trial-fullaccess-light-v01.png`  
  Why: keeps pricing comprehension simple while reinforcing only approved model.

- **Supporting technical trust image (optional section 3/6):** `sim-proof-validation-process-panel-light-v01.png`  
  Why: useful if a secondary proof inset is needed for credibility.

Primary vs supporting:
- Primary: hero + flow + pricing-support
- Supporting: connection + reliability + validation

## C) Design/build notes

Spacing/hierarchy:
- Use a consistent 12-column desktop grid.
- Section vertical rhythm: 88-120px desktop, 64-88px tablet, 48-64px mobile.
- Keep hero copy block max-width ~560-640px for readability.
- Avoid stacking too many proof visuals above the fold.

Image size/crop guidance:
- Hero module target aspect: 16:9 source, allow 3:2 fallback.
- Benefit/support proof crops: 3:2 or 4:3.
- Flow section image: medium-wide crop to preserve movement context.
- Pricing support image: card-focused 16:10 or 3:2.

Where copy should stay short:
- Hero subheadline (1-2 lines preferred)
- Benefits card body (1 sentence each)
- Final CTA support line (single sentence)

Where visuals should lead:
- Hero
- How-it-works
- Pricing support context
